# pew2

Mobile remote control for **desktop coding agents** (Claude Code, Codex, Gemini CLI, GG Coder). The agent runs on the user's machine over the [Agent Client Protocol](https://agentclientprotocol.com); the phone is a client that watches the same session, prompts it, and answers its permission requests. **Transport + UI, not an agent.**

- `packages/protocol` — Zod schemas for provider manifests + the daemon↔relay↔app envelope, and the E2E crypto. Authoritative for both sides; `schemas/*.json` is autocomplete only, synced by hand.
- `packages/daemon` — spawns agents, speaks ACP over stdio, owns the seq'd session log, warm spares, probe cache, prefs, push, and the `pew2` CLI.
- `packages/relay` — Cloudflare Worker + Durable Object, one room per pairing; routes opaque sealed frames and stores nothing.
- `packages/app` — Expo/React Native client. `providers/*.json` — one manifest per agent; adding a file is the whole integration.

**Flow:** app `session.prompt` → relay → daemon → ACP `session/prompt`. Agent `session/update` → `SessionLog.append()` stamps a gapless `seq` → broadcast to **all** clients. ACP is one-client-to-one-agent; a phone and a desktop share a session only because the daemon owns the log, and reconnecting clients replay from a cursor because **ACP never re-sends**. Do not "simplify" that away.

**Live sync across devices** rides on the same fan-out: `pew2 chat` (`cli/chat*.ts`) is a terminal client of the same log, half-typed text travels as ephemeral `session.draft` frames, and the phone's computer icon (`desk.open`) either opens a `pew2 chat` window on the Mac or hands the conversation to the agent's own app (`target: "native"`, OG Coder in iTerm) while the daemon keeps the phone in the loop. Keep-awake (`keep-awake.ts`) holds a sleep assertion only while someone is using the machine. All of it is additive on the wire: `drafts`, `keepAwake`, `desk` on the `providers` frame are optional and absent means "older daemon".

## Gotchas — daemon

- **Register the permission resolver *before* notifying the UI** (`acp/connect.ts`) — a synchronous answer finds no pending entry and the agent hangs ("tap Approve, nothing happens"). The mirror rule: `close()` resolves every still-pending entry with `null`, which the request handler answers as ACP `cancelled`. An unresolved resolver keeps the whole connection closure alive for the life of the process.
- **Every session close goes through `closeSession()`** (`index.ts`) — the reaper, the `MAX_LIVE_SESSIONS` cap, a disabled provider and `closeAll` all used to do their own subset, and only shutdown discarded the attachment files, so every photo sent to a later-reaped conversation stayed in the tempdir for the daemon's lifetime.
- **A session blocked on an unanswered permission is reaped after an hour** — `working` is true for the whole wait, so the idle reaper never saw it and one unnoticed request pinned an agent plus a live slot for ever. Closing is not answering: nothing times a permission out (the phone can still answer for that hour), and the *whole session* goes, which the app already survives via `activeSessions` + `needsResume()`. The gate is `permissions.size > 0`, so a long working turn is untouched, and `lastUsedAt` is re-stamped when the request is registered so the clock starts at the question.
- **Preview lists websites, not listeners** (`preview.ts` `previewSites`) — `preview.list` drops the daemon's own port (`PEW2_PORT`, default 8787, which is also a common dev port and once ranked first, so "Open" showed pew2's "pairing token required") and then asks every other listener `GET /` on 127.0.0.1 in parallel (1.5s each), keeping only those that answer HTML or a redirect. Without that the list was adb, Ollama, OneDrive and IDE helpers. The snapshot check uses the looser `previewablePorts` (anything but pew2's own port), so a slow page can still be pictured. Probes stay on loopback and on ports the daemon itself just saw listening.
- **"Open in OG Coder" starts the agent by its full path** (`commandPath` in `providers/registry.ts`). The iTerm window runs `/bin/zsh -lc`, a login shell that never reads `~/.zshrc`, so an agent installed with pnpm (`~/Library/pnpm`, added to PATH only in `.zshrc`) was "command not found", the window closed at once, and iTerm handed back `missing value` ("Can't get current session of missing value (-1728)"). That error now reads as "OG Coder closed as soon as it opened" on the phone.
- **Spawned children need `error` *and* `spawn` listeners** — an unresolvable command emits `error` async, and unhandled it kills the daemon and every other session.
- **The useful half of an agent failure is JSON-RPC `data.details`** (sometimes double-encoded), and it arrives twice: as message text, then a rejection. `humanError()` (`errors.ts`) normalises at the one point all transports share. A clean exit is not an error — closing a session always fires `kind: "exit"`.
- **`resolveWorkspace()` (`workspace.ts`) is the only cwd default** (explicit → `PEW2_WORKSPACE` → daemon cwd → home). Under launchd cwd is `/` and agents treat cwd as project root — GG Coder died on `mkdir '/.gg'`. Session start *and* the capability probe go through it; a third spawn path reintroduces the bug.
- **A client's `cwd` is honoured only via `knownProject()`, and that check has to outlive the process** — the app re-sends its chosen project on every reconnect and every new conversation, for days. Browsed paths lived in memory alone, so a daemon restart made a genuine pick unknown, and both readers failed *silently*: `workspace.status` answered with the agent's previous project (the composer named a repo the user never picked) and `session.start` then refused the same path. Acceptance is written to `known-projects.json`, and the check reads the probe cache when no probe has landed yet — the app asks in the same breath as the probe it triggers, so recognition must never be a race against a spawn. `session.resume` still falls back rather than refusing (it arrives before the probe), but it may not *guess a project*: it takes the cwd the agent recorded for that conversation, because dropping to the provider's last workspace reopened a chat about one repo with the agent rooted in another.
- **Two prefs files, deliberately.** `config-prefs.json` (one file for all providers — read-modify-write it) seeds the *next new* session; `session-prefs.json` is replayed on `session/load`, because ACP resumes a transcript but hands back the agent's *default* selectors. Never apply the provider pref to a resume — that rewrites a desk-started conversation to match the phone's last pick.
- **Session ids die with the daemon; the app's list does not.** `needsResume()` (`agentHistory.ts`) is the single rule for opening a conversation, and an undefined `activeSessions` (older daemon) means *assume live*. Without it a restarted daemon answers `Unknown session '<id>'`.
- **Projects fold from the *uncapped* session list**, before `SESSION_HISTORY_LIMIT` (`projects.ts`) — the capped list is a recent-work window, so grouping it hides every repo not touched this week. Message counts hydrate per project on demand, never at probe time. The capped list itself is **stratified, not a flat slice** (`stratifiedSessions`, same file; the app mirrors it in `sessionHistory.ts`): one row per project first, then the newest overall to fill the window. A flat newest-30 across twenty-eight projects left a quiet repo with no row at all, which on the phone reads as the conversation having been lost — the recurring "my chat disappeared" report was never data loss.
- **The probe cache is stale-while-revalidate, not permanent** (`PROBE_TTL_MS`, `index.ts`) — it was memoised for the daemon's lifetime and refreshed once, on the first cache hit after boot, so every session and project started at the desk over the following days was invisible to the phone until a restart. A refresh must run *beside* the cached entry (never clear `probes` up front, or readers block on the reprobe and get nothing when it fails) and must not be delegated to `warmProvider`, which returns early whenever a spare is parked.
- **Warm spares: check `spares.has(id)` before booting, and gate readiness on `spareReady`, not `warming`** — a disk-cached probe skips the boot path, so the wrong flag duplicates an agent or blocks on a history read.
- **A version 1 `disabled.json` reads as empty, and that looks exactly like a bug** (`providers/enabled.ts`) — the file is retired rather than migrated, because the old setup wrote agents to it for merely failing a verify, so it is not a record of anything the user chose. The visible symptom is every agent they thought was off being probed and listed again, with an auth stack trace per uninstalled one on every connect. It is silent by design: nothing tells the user their list was dropped. `pew2 providers disable <id>` rewrites at version 2, and the old list survives as `disabled.json.v1.bak`. Before debugging "why is this agent still showing", check the `version` field.
- **Two transports, one handler.** `handler.ts` owns every message case; `server.ts` (LAN) and `relay-client.ts` (remote) only supply `reply`/`broadcast`. A case added to one makes local and remote drift.
- **"Open in OG Coder" is a handover, not a second agent** (`native-desk.ts`, `acp/ggcoder-mirror.ts`, `Daemon.openNative`). The ACP session is closed through `closeSession()` and the user's own `ogcoder --resume <id>` runs in iTerm, so one process writes the conversation. The phone sees a *mirror session* (same `agentSessionId`, fresh id): prompts/drafts are typed into the window by iTerm `write text … newline NO`, and the conversation's `.jsonl` is tailed back into the log from a baseline taken *before* the window opens. Ink reads one write as one key press and a multi-character write as a paste, so drafts go **key by key** (backspaces to the common prefix, then new characters, each its own write; whole-line rewrites left a stuck "[Pasted text]" block), control keys are never in the same write as text, and Enter waits out OG Coder's 100ms paste window. Pills: model is OG Coder's own `/model <id>`; thinking is Shift+Tab pressed **one at a time with the status line read back after each** until it shows the level (OG Coder's cycle is per model, so counting presses off the advertised list landed on the wrong level); plan mode is refused in words, because OG Coder only enters it through its own `enter_plan` tool. **The window is read back every 800ms** (`nativeReadScript` → `parseOgCoderScreen`): the input box becomes a `session.draft` from `"desk"` (so typing *and clearing* at the desk reach the phone) and the status line's model / `Thinking x` / `Plan on|off` become the phone's pills. The read is skipped while the phone's own keys are landing (`typer.busy`, 1.2s quiet) and while a pill change is being driven, or the half-typed screen reads as a desk edit and the two sides fight; trailing spaces are screen padding, so compare `trimEnd()`. The screen parser depends on OG Coder's layout (` > ` under a `▄`/`─` edge, `│`-separated status cells) — if OG Coder's TUI changes, `parseOgCoderScreen`'s test fixture is the place to update. Closing/reaping a mirror only stops mirroring; the window is the user's. **Each mirror is its own session** (own pew2 id, own iTerm session id, own `agentSessionId`), so several OG Coder windows map one-to-one to their phone conversations; timers find their session by the `NativeSession` object, never a captured id, because **a reopen re-keys the mirror** (`reopenNative`: fresh id, log copied, replayed whole) — reopening under the same id had every replayed event skipped by the phone's cursor and showed the conversation empty. **A new conversation can start natively** (`desk.open` with no `sessionId` but `providerId` + a `knownProject` cwd → `openNativeNew`): the app starts plain in the project, the daemon waits for the `.jsonl` it writes (`findNewConversation`, files newer than the open, not seen before) and announces it as a *new* session so the phone's empty screen claims it. **Turn ends come from `turn_metric`, not a run journal:** OG Coder's own screen writes no `run_started`/`run_finished`; it appends a `turn_metric` as each model call ends (live) and the turn's messages in one batch when it is over, either side of the last metric. A metric with `stopReason` `tool_use`/`pause_turn` means work is under way; any other ends the turn once the file has been quiet ~0.8s. A user line with no metric settles after 5s. Waiting for `run_finished` left the phone "working" forever after every desk-side turn. Backstop: the status row above OG Coder's input (`⠋…` spinner = busy, `✻ …`/"Ready to go" = idle), two agreeing reads, and a 4s grace after a turn starts.
- **Relay: `ctx.acceptWebSocket()`, never `server.accept()`** — only that permits Hibernation, and the auto-response must match the daemon's exact `{"t":"ping"}`. It **requires `deviceId` on `/connect`** (400 otherwise) and **must forward `hello`, not answer it** — that is the daemon's only signal an app joined. A daemon socket is evicted only after it stops answering keepalives; "newest wins" let a stranger hold the machine offline.
- **The relay is untrusted by design.** Room id is derived one-way from the pairing token, frames are sealed per-message, the daemon won't start without a key, `PEW2_TOKEN` is refused below 32 chars (that string *is* the entropy), and a client `cwd` is honoured only via `knownProject()`. `/health` stays open so `doctor` separates "not running" from "unpaired".
- **Images are answered as a `reply`, never a session event** (`images.ts`) — in the seq'd log they'd re-download on every reconnect. The path comes from the agent, so it is realpath'd (macOS `/tmp` is a symlink) and confined to session cwd + `tmpdir()` + `/tmp` (agents save screenshots to `/tmp` by name, and macOS `tmpdir()` is `/var/folders/…`, not `/tmp`; only image extensions are ever served). OG Coder never stores a picture a tool read from disk: its `.jsonl` has the sentence `[Session storage omitted duplicated image data; read the source again at <path>.]` instead, which `historyToolImages` turns back into a `resource_link` to that path (tool results only). Other pictures it stores as `gg-session-asset:v1:<sha256>` markers with the bytes in `<file>.assets/`; `messageDisplayUpdates({ assetDirs })` reads them back, and an unresolved marker is dropped rather than painted as a broken image. The 8MB ceiling exists because base64 inflates by a third, keeping a frame under the Durable Object's 32 MiB receive limit.
- **Attachments go the other way and land in tempdir, never cwd** (`attachments.ts`) — cwd is a git repo whose uncommitted count is on screen, and `git add .` would commit them.
- **Prompt blocks come from `promptCapabilities`** (`acp/promptBlocks.ts`) — an unadvertised block is a protocol error. A `resource_link` is advisory, so anything sent as a link is **also named by path in the text block**, or attaching to a non-vision agent silently does nothing.
- **The log is trimmed on a timer as well as at startup, and always *in place*** (`logs.ts`) — a startup-only pass bounds the file by restarts, and this daemon is a launchd service that goes weeks without one, so a provider failing its probe every few minutes wrote until the disk did. `startLogRotation()` re-checks hourly and `unref`s its timer, because housekeeping must never be what keeps the process alive. Never *rename* to rotate: the supervisor holds an open descriptor to the path it opened, so the daemon would go on writing to `daemon.log.1` while `daemon.log` sat empty. Truncation is safe only because every supervisor opens the file in **append** mode (launchd `StandardOutPath`, systemd `append:`, `>>` under Task Scheduler) — otherwise the next write lands at its old offset and leaves a hole of NUL bytes.
- **Drafts (`session.draft`) are never logged** — held in memory, latest per conversation (`""` = not started), re-broadcast with `from` = the proved sender, cleared on prompt/start/close, and sent to a joining client after `catchUp` on *both* hello paths. A seq'd draft would replay keystrokes on every reconnect.
- **The keep-awake child must die with the daemon** (`keep-awake.ts`) — `caffeinate -w <pid>`, killed on release and in `closeAll`, and inert until `startKeepAwake()` (only `server.ts` calls it) so a test Daemon never spawns one. The pref `keep-awake.json` is re-read every 30s tick.
- **`pew2 chat` connects as `pew2-cli@<host>#chat-<rand>`** — the CLI prefix is what keeps it from claiming the phone's pairing, and `waitForDevice` ignores any `isLocalWatcher()` id so a chat window never reads as "phone paired". It re-launches itself into its own iTerm/Terminal window with `--here --project <git root>` (the new window starts in `~`, so the project must travel as a flag), and a project window follows only sessions whose cwd is inside it — learned from `workspace.status`, since `activeSessions` names no project. A new conversation from it sends `workspaces` for the project first: `session.start`'s cwd is honoured only via `knownProject()`, and browsing is what publishes a path. Not-yet-started drafts carry no project, so project windows neither send nor apply them.
- **The daemon opens windows on the user's screen, so treat it as a launcher, not a shell** (`desk.ts`). Only a session id the daemon holds reaches the command line: the project is that session's recorded cwd and the program is pew2 itself, both `shellQuote`d (twice over inside `zsh -lc` inside AppleScript — test with a path containing a space). Under launchd, AppleScript is an Apple Event from `bun`: the first call to iTerm *blocks* on macOS's "bun wants to control iTerm" prompt (hence the timeout and `PENDING_NOTE`, and the osascript is left running so the window still opens once answered), and a refusal is `-1743`, which falls back to Terminal via a `.command` file — that path needs no permission at all. Repeat taps within 4s open one window. **"Computer Screen" (`desk.capture`)** is the daemon's own `/usr/sbin/screencapture -x` (sbin, not bin) shrunk by `sips` to a ≤1800px JPEG, read into memory, temp folder removed, and *replied* (never logged or broadcast) for the phone to attach; no agent turn. Under launchd the capture is `bun`'s, so it needs Screen Recording for `~/.bun/bin/bun` once; until then it exits non-zero or leaves no file, and the phone is told where the switch is (`SCREEN_PERMISSION_NOTE`). Concurrent taps share one capture. **Closing from the phone (`desk.close`)** is keyed by `agentSessionId` (mirror session ids change on reopen) and announced as `desk.windows`, which fills the phone's icon and puts Close first in its menu (at most two actions: Android's alert holds three buttons with Cancel). OG Coder is quit as by hand — input emptied, then Ctrl-D — and a `pew2 chat` window with Ctrl-C (its raw input reads it); a window still there after 5s is closed outright with AppleScript `close`. Refused while the mirror is mid-reply. Only iTerm windows can be closed: `Desk.open` returns the iTerm session id (kept in the daemon, never sent), Terminal's `.command` windows are not tracked. Chat windows closed by hand drop out on the 3s alive poll.

## Gotchas — app

- **The drawer's project row needs its own gesture** (`Sidebar.tsx` `tabsGesture`): the drawer's close swipe (`useDrawer` `drawerSwipe`, passed in as `closeGesture`) covers the whole drawer and claims any sideways move first, so the row's horizontal list never scrolled. A `Gesture.Native()` on the row `blocksExternalGesture(closeGesture)`. Checking it on Android: the drawer stays mounted off-screen when closed, so `uiautomator` still lists its "Close menu" button; use a screenshot.
- **The composer is never disabled by the network** (`App.tsx`) — a phone is offline routinely, and locking the input was locking the user out of writing anything down at all. A send with no socket is queued in `outbox.ts` and delivered on reconnect; only `daemon.fatal` (rotated key, version mismatch) locks it, because nothing typed there could ever go. Queue rules: a start and its first prompt are queued **together or not at all** (a lone request opens an empty conversation), a second message joins the start already waiting rather than opening its own thread, only **one** `session.start` is in flight at a time (`pendingStart` holds one id), and `session.started` re-addresses everything queued against the `pending:` key or a dead pre-restart id. `busy` and the turn clock start when the frame actually leaves the phone — never when it was typed, or the duration is a measure of the tunnel. Agents are *discovered*, so the list is cached (`providerCache.ts` → `preferences.ts`) or a cold start offline knows of no agent to address a new conversation to; it is applied only over an empty list, never written empty (that frame means "still probing"), and cleared on unpair.
- **Desktop images are a byte-capped LRU, and both maps move together** (`imageCache.ts`, `useDaemon.ts`) — a `data:` URI retains ~21MB per full-size image and nothing evicted them. `requestedImages` is the fetch-dedup guard, so a uri dropped from `images` but left in it is a permanent spinner; `putImage` returns the evicted list precisely so both can be cleared, and eviction is computed *outside* the `setImages` updater because an updater may run twice. `ChatImage` re-requests whenever its entry is missing, which is what makes eviction cost a round trip instead of a blank cell.
- **Turn ids are `${sessionId}:${seq}`** — `seq` restarts per session, so seq alone collides and React merges unrelated turns.
- **Filter `session.event` against `sessionRef.current`; `session.idle` is deliberately *not* filtered** — it is the only signal a background conversation finished, so it applies per session and is never replayed.
- **Replay overlaps the live stream** — drop events at or below the per-session cursor (`cursors.ts`). A replay batch must never set `busy` or raise `permission` (`replayFold.ts`): perpetual spinner, phantom approve sheet. It *does* carry the last `usage_update`.
- **An open approval is state, not an event** — so a catch-up carries `permissions` beside `working`, because the logged `permission_request` is skipped as history and nothing times a permission out at either end (a phone that dropped signal mid-request left the agent stopped for ever). Absent means "an older daemon said nothing", `[]` means "none pending" and dismisses the sheet; the request is filed on the *session* row, so it survives switching conversations.
- **Chunk merging is decided by the *seam*, not the provider** (`chunkJoin.ts`) — some agents stream tokens, others send whole messages; whitespace either side means continue, a sentence ending against a capital gets `\n\n`, and a real char must precede the stop or `"3."`+`"14"` splits.
- **Map `user_message_chunk`, not just live prompts** (`chunks.ts`) — GG Coder replays user turns that way. A turn is empty only with no text *and* no images (tool-generated images have no chunk).
- **Context % comes from optional ACP `usage_update`** — an agent that sends none gets **no reading, not 0%**; the window is per model, so readings don't compare across a switch.
- **The transcript is FlashList v2 and owns its scroll** (`ui/ChatThread.tsx`): `maintainVisibleContentPosition` + `startRenderingFromBottom` is the whole mechanism. Never scroll imperatively from `onLayout`/`onContentSizeChange`; the `threadBottom` catch-up is grow-only and unanimated (the dock resizes around the keyboard, and two curves = the thread re-seating). Cells recycle, so a mount is not a new message.
- **The composer expands on focus, text or attachments — deliberately *not* on `busy`** (`ui/Composer.tsx`) — a working agent used to hold the pill open, so dismissing the keyboard mid-turn left a tall empty box standing over the transcript for the length of the answer. It bought nothing: the action row is always the bottom 58pt, so stop is exactly as reachable in the collapsed pill. It also poisoned the dock inset, since the resting height is recorded with the keyboard down (`recordDockHeight`) and the transcript then kept the taller number too.
- **The app rotates (`orientation: "default"`), so a screen dimension read at import is a bug** — it is the launch orientation's number for the life of the process. Landscape exists because half of what an agent replies with is wide (tables, diffs, command lines), and the layout that follows it is all *hooks*: `useDrawerWidth` (the panel's width and the distance the pane is pushed must be one number, or the drawer opens to a gap), `useSheetVisibleRows` / `useSheetMaxContentHeight` (a sheet is bottom-anchored, so a card taller than the screen loses its **top** — the title, the grabber, and an approval's request text, while the options it belongs to stay visible below). Horizontal safe-area insets matter only sideways and are not the same case as top/bottom: a notch on a long edge is not softened by a `CanvasCover`, it hides content outright, which is why the pane takes `edges={["left", "right"]}` while staying full-bleed vertically. The composer's ceiling is a *line count* derived from viewport height, and the box's max height and the field's internal-scroll threshold must come from that one number or a draft is clipped with no way to scroll to the rest of it.
- **`@pew2/protocol` imports work only because `metro.config.js` maps the `.js` suffix back to `.ts`.** If a bundle dies on "Unable to resolve", suspect that shim first.
- **Dictation replaces the *open segment*, never the draft — and `isFinal` is a hint, not a boundary** (`transcription.ts`). Each interim restates the whole utterance, so appending stutters; but `continuous: true` puts many utterances in one recording and the recogniser starts each from empty, so replacing everything delivers a paragraph as its last phrase. Hence `typed + committed + segment`, not one string. **Do not "fix" this by trusting `isFinal`** — iOS 18 stopped delivering a real one, Expo infers it from `speechDuration > 0` which repeats mid-session, and a segment announced final can still be revised. The boundary is read off the transcripts instead: a prefix match (case- and trailing-punctuation-insensitive) revises the open segment, anything else opens a new one.
- **Pure modules stay Expo-free** (`pairing.ts`, `hapticsPolicy.ts`, `notificationPolicy.ts`, `transcription.ts`, `permissions.ts`); native binding lives in the `ui/` twin. Importing `expo-*` into the pure half breaks `bun test`, which cannot parse React Native's Flow syntax.

- **Never send `session.draft` unless the daemon announced `drafts: true`** (`draftSync.ts` `shouldSendDraft`) — an older daemon answers an unknown type with `unknown_message`, and this app reads that code as a refused push token (`onPushRegistered(false)`), so ungated keystrokes would silently turn notifications off. Drafts bypass `post()` (which flushes the stream batch) and the outbox (ephemeral: offline means dropped), and a pending trailing draft is dropped, never re-addressed, when the conversation on screen changes.
- **A remote draft goes through a listener ref, never App state, and must not echo** (`useDaemon` `draftListener`, `ComposerDock.applyRemoteDraft`) — keystroke-rate frames through `setState` re-render App. `applyRemoteDraft` sets the text without calling `onDraftChange`; it is skipped while dictation is listening (the recogniser owns the draft) and when the text already matches. Incoming drafts are handled *before* `resetStream()`, so one arriving mid-reply does not flush the batch.
- **The computer icon asks only when there is a choice** (`deskChoice.ts`) — with the provider in `desk.native` it offers "Open in OG Coder" / "Open in pew2 chat"; otherwise it taps straight through, and with no `desk` at all it is not rendered. A native open sets the resume expectation so the mirror's `session.started` takes the screen, and clears it if the open fails. Success is silent; only a failure or a note (iTerm permission) raises an Alert. Keep it subtle — a dim 16pt glyph, no glass.

## Gotchas — calls with Pew (upstream's, plus Android)

- **Calls are upstream's (0.9.24+), not this branch's old GPT-Live.** Merged 20 Oct: our `voice.start/answer/stop` wire, `voice/{config,host,manager,openai,prompts}.ts`, `VoiceScreen`, `VoiceBar`, `voiceSession.ts`, `pew2 voice key` and the composer's headset button were retired; upstream's `voice/controller.ts`, `CallScreen`, `useVoice`, `VoiceSettingsSheet` (Ring me, call history) took over. Pew signs in with the OpenAI login an agent already has (`~/.gg/auth.json` `openai`), never refreshing an agent's token. `~/.pew2/voice.json` is no longer read.
- **Android is ours on top of upstream's iOS-only parts.** `ui/androidCall.ts`: InCallManager routes the call (earpiece, Bluetooth after the runtime `BLUETOOTH_CONNECT` grant, speaker button via `setForceSpeakerphoneOn`), and `modules/voice-call-service` (microphone foreground service) starts when the call goes live so a locked screen keeps the mic. Android 14 only allows that service while the app is in front with the mic granted.
- **Android rings itself from `voice.ring`.** Upstream rings only through CallKit (VoIP push via the relay's `/voip`). The daemon's `ring` hook now also broadcasts `voice.ring` (same moment, same `ringId`); `useAndroidRing` plays `assets/ringtone.wav`, raises a banner when backgrounded (its tap opens the call via `onVoiceRequest`), shows `IncomingCallCard`, and reports declined/missed with `voice.end` under the ring id. A phone CallKit rings (`canRing`) ignores the frame, so nothing rings twice. No consent yet: banner only. Untested on a real call (needs a ring and an answer on the phone).
- **Models and limits by voice** (`voice/models.ts`): `set_model` / `list_models` (run by `runModelTool`, async) match a spoken name against the session's own model menu (`daemon.voiceModels`), switch it through `setConfigOption` (a native OG Coder window gets `/model`), and broadcast `session.config` so the pills follow. `start_chat` takes `model` and switches before the first message. A failed turn's reason is kept (`noteTurnEnd`, from `runTurn`), and `hitLimit` over it plus the last lines sets `SessionStatus.limit`, shown in the briefing ("HIT A USAGE LIMIT") and `get_status` (`hit_usage_limit`). Claude Code's menu is Claude only, so Pew offers OG Coder on GPT via `start_chat`.
- **A ring when handed-over work is done** (`controller.endCall` → `handedWork`): a call that sent a chat work (`tell_agent`, or `start_chat` with text) books `callWhenDone` on hang-up, only with Ring me on and no callback already booked. `callbackAbout` makes the answered call open with that project's news (`callbackLines`). Ring me defaults to Off, which is why Pew "never called" before.
- **Transcription is pinned to English** (`buildSessionConfig`, `language: "en"`; accepted by client_secrets 20 Oct). Pew hears the audio itself; this fixes captions and the saved call history.
- **Testing a real call from the Mac**: start the call on the phone, then `say -r 170 "…"` near it at volume 80; the transcript lands in `~/.pew2/voice-threads.json`. A locked phone can't be unlocked over adb (secure keyguard); ask for an unlock and raise `screen_off_timeout` meanwhile, then put it back to 30000.
- **The daemon's `observe`/`notify` hook is gone** (it fed only the old GPT-Live). Keep-awake still runs off `evaluateAwake()` in `prompt-queue.ts` and the native turn paths.

## Workflows

- **`npm run daemon` is not the server** — it prints JSON and exits. The WebSocket server the app talks to is `bun run packages/daemon/src/server.ts` (8787, `PEW2_PORT`). The `echo` provider is a real ACP agent needing no key or network — the only offline way to exercise the pipeline.
- **Live loop:** start that server, then `cd packages/app && npx expo run:ios`, scan the printed QR. **Expo Go can no longer load this app** (keyboard-controller, glass, picker, speech are native). After `npx expo install`, **restart Metro** — a stale graph reads as a module missing at runtime.
- **A `Sheet`-based harness renders blank on `expo start --web`** — `WorkletsError: createSerializableObject should never be called in JSWorklets`, and it takes the whole tree with it (`NewChatSheet.harness`, `MessageSheet.harness`; `ChatThread.harness` is unaffected). Run those with `npx expo run:ios`, and relaunch between screenshots: fast refresh keeps state, so an edited fixture never moves and the card is caught mid-spring.
- **`pew2` is not on PATH until `cd packages/daemon && bun link`.**
- **The app's two looks live on as starter apps in `riazmohamed/design-boilerplates`** (private): `classic/` is this app's design at `be86304`, `stage/` at `1edd3cf`, each an Expo SDK 54 app that opens on a showcase of every token and component, with no pew2 logic. A design change worth reusing elsewhere gets copied there too. Two traps found building them: Skia 2.3+ needs `trustedDependencies` or bun skips the postinstall that fetches its native libraries (the Android build then fails on a missing `libsvg.a`), and `StageScroll` needs an explicit height on the scroll view, because its host only shrinks; `flex: 1` collapses to nothing and the screen is blank.
- **Know which half you changed, because they ship on separate rails and neither carries the other.**
  - `packages/daemon`, `packages/protocol`, `providers/*.json` → **binary release**. Tag `v*`; `release.yml` cross-compiles, checksums, and publishes to `releases/latest`, which is the path `install.sh` / `install.ps1` resolve by name. Users re-run the curl line. The per-target build artifacts are a handoff to the release job only, so they carry `retention-days: 1` — on the default 90 days they exhausted the account's artifact storage quota, which silently blocked artifact uploads across every repo.
  - `packages/app` → **IPA**. `scripts/build-ipa.sh`, then Transporter and App Store review — days, not minutes, and the user cannot be told to hurry.
  - `packages/relay` → `npm run relay:deploy`. Ships instantly and independently of both, since it only routes sealed frames.
  - The manifests are **compiled into the binary**, not read from disk (`release.yml` verifies the count), so adding a provider is a daemon release even though it is only JSON.
- **A wire change is both, and the daemon is the half that has to tolerate the gap.** Nothing negotiates a version: the app is on the App Store's clock while the daemon updates the same day, so every new field is optional on arrival and absent means "older peer", never "none" — the reason `activeSessions`, `permissions`, `projects` and `commands` all distinguish absent from empty. Ask "does an old app talking to this daemon still work, and an old daemon to this app?" before assuming a change is daemon-only.
- **Putting the app on a plugged-in Android phone needs no Expo or EAS:** `cd packages/app/android && JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ANDROID_HOME=~/Library/Android/sdk ./gradlew assembleRelease`, then `adb install -r app/build/outputs/apk/release/app-release.apk` (adb is in `~/Library/Android/sdk/platform-tools`). The release build is signed with `android/app/debug.keystore`, so it installs over the previous build and keeps the pairing. Before trusting it, check the bundle actually changed: `unzip -p` the APK's `assets/index.android.bundle` is Hermes bytecode, so `strings | grep` misses text — extract it and `grep -a -F` instead. `adb shell input tap` takes *device* pixels (1080×2376 override on the OnePlus), not screenshot pixels.
- **Known, not yet fixed: after a daemon restart the Android app may not reconnect by itself.** Seen twice on 14 Oct: the relay came back `online` but the phone stayed on "Connecting…"/a stuck stop button for over a minute until the app was force-stopped and reopened (`adb shell am force-stop io.github.kenkaiii.pew2` then `monkey -p … 1`). Check this after any restart before testing on the phone.
- **This branch merges KenKaiii/pew2 (`upstream`), it does not rebase on it.** Remote `upstream` = github.com/KenKaiii/pew2; merge `upstream/main` and keep both sides (upstream moved App.tsx into `src/Pew2Screen.tsx` + `ui/ScreenTopBar.tsx`, useDaemon into `src/daemon*.ts`, and the Daemon class into `packages/daemon/src/daemon/*.ts` layers that reach our code through abstract hooks in `daemon/state.ts`: `notify`, `evaluateAwake`, `promptNative`). Our voice, desk/OG Coder handover, drafts, keep-awake and Agents catalog live on top of that. Upstream PR #6 (AutomationGods fork, 2,308 private-notes files) is deliberately not taken.
- **Testing the release app on the Android emulator:** the release APK refuses cleartext `ws://`, so a LAN link does not pair; point a throwaway daemon (`PEW2_HOME=/tmp/… PEW2_PORT=8899`, plus `PEW2_EXPERIMENTAL=1` for the offline echo agent) at the relay (`pew2 relay <url>` with that PEW2_HOME) and type its `wss://` link into the paste box. `adb shell input text` drops characters in long strings and mangles the first few while the keyboard opens: type 12-char chunks, the first characters one at a time, and read the field back with `uiautomator dump` before tapping Connect. Build arm64-only (`-PreactNativeArchitectures=arm64-v8a`, ~68 MB) or the emulator's default 6 GB data partition fills; wipe with `-wipe-data -partition-size 8192` if it does. A pairing admits one device: clear `claimedBy` in the throwaway `pairing.json` to pair a fresh emulator.
- **Agent on/off lives in `~/.pew2/disabled.json`** (`providers/enabled.ts`; CLI `pew2 providers enable|disable <id>`; phone Connection › Agents via `provider.enable` + the announce's `catalog`). GG Goals has no manifest of its own: it is on exactly while `ggcoder` is on (`providers/catalog.ts`). `setEnabled(ids, enabled, env)` takes env third: a test that passes it elsewhere writes the user's real file.
- **Restarting the daemon drops OG Coder mirrors but not the OG Coder windows** — the window is the user's process, not a child, so it survives `launchctl kickstart`; the phone just stops typing into it until it is opened again from the phone.
- **Closing an OG Coder window hands the conversation back to a headless agent, with no code of its own** — `watchNativeWindow` polls every `NATIVE_ALIVE_POLL_MS` (3s), kicks the mirror so the agent's last words reach the phone, ends any turn, then `closeSession()` + `announceProviders()`. The app sees the id leave `activeSessions` and sends `session.resume` (the same path that survives a daemon restart), so the conversation carries on headless with its full history; a phone offline at that moment does it on reconnect. What is *not* carried over is a turn running in the window when it closed: the window was the agent, so that work stops and must be asked for again. Closing a `pew2 chat` window or any other terminal changes nothing, since the daemon is a launchd service, not a terminal's child.
- **A missing button on the phone is usually a stale build, not a bug** — the app ships on its own rail, so a feature committed after the last `assembleRelease` (the empty-chat computer icon landed six minutes after the APK on the phone was built) is simply absent there. Compare `adb shell dumpsys package io.github.kenkaiii.pew2 | grep lastUpdateTime` against `git log` before debugging the render condition.
- **A daemon-only fix still needs the running process restarted.** Development runs from source (`bun run packages/daemon/src/server.ts`), so an edit changes nothing until that process is killed — a long-lived daemon holding stale in-memory state is exactly the class of bug that hides here.
- **`bunfig.toml` preloads `scripts/test-setup.ts`, which gives each run its own `TMPDIR`.** Tests `mkdtemp` constantly and essentially never clean up — 27,645 directories and 257MB had accumulated — so the run is retargeted at one root and swept in `afterAll`. Not `process.on("exit")`: the test runner ends the process without running exit hooks. A test that asserts a literal system temp path will fail here, and that is the fix, not the path.
- **`children.ts` handles SIGINT/SIGTERM/SIGHUP only when nothing else does** — a default-disposition signal runs no `exit` hook, so Ctrl-C on the CLI or on a `bun test` run orphaned its agents to pid 1. The handler bails when `process.listenerCount(signal) > 1` (that is `server.ts`'s graceful shutdown, which wants its 500ms grace) and otherwise kills owned children, removes itself and re-raises — without the re-raise, importing this module would make a process survive its own Ctrl-C.
- **Keep `npm test`'s explicit source roots.** `bun test packages` walks 13k dirs, blows past Darwin's OPEN_MAX, and spawned children then read back empty with exit 0 (Bun #32067) — correct code, red tests. Add a root when a new package gets tests.
- **Two checks need a server already running and are not in `npm test`:** `npm run relay:dev` then `npm run relay:check`; and, with the daemon up, `bun run packages/daemon/src/testing/e2e-check.mjs`. `wrangler dev --local` silently breaks WebSocket upgrades, so `relay:dev` does not pass it.
- **`providers validate` only proves the JSON parses; `providers verify <id>` spawns and prompts the agent** — always finish with `verify`.
- **The Android CI job is the only native-config check** — `ios/` and `android/` are gitignored, so a plugin collision or autolink failure is invisible to typecheck/test. iOS is verified locally (`expo prebuild --platform ios` + `pod install`); macOS runners bill 10x.
- **iOS config traps** (`app.json`): two plugins must never claim one Info.plist key (the later silently wins — `expo-camera` owns `NSCameraUsageDescription`, `expo-media-library` owns `NSPhotoLibraryUsageDescription`, so `expo-image-picker` declares neither); `ios.infoPlist` ships verbatim, so no `"//"` comment keys; `ITSAppUsesNonExemptEncryption: false` or every EAS build stops for a manual answer.
- **The EAS iOS build image is pinned** (`eas.json`) — Xcode 26.0 desyncs `react-native-keyboard-controller`'s per-frame numbers, since UIKit gates on the SDK built against. Never `auto`/`latest`; if the keyboard is off again, suspect this line first.
- **Shipping an `.ipa` is `packages/app/scripts/build-ipa.sh`** — `eas build --local` runs the same pipeline on this Mac in ~3 min and costs no build credits, where the cloud build is metered and queues. It leaves one `pew2-build<N>.ipa` on the Desktop for Transporter, deletes the previous one *after* a successful build, and refuses to hand over anything signed `get-task-allow=true` (a development profile uploads fine, then gets rejected by email hours later). Still needs an Expo login even offline of the cloud builder: `appVersionSource: remote` means the build number is incremented server-side, so an anonymous run dies after installing pods. `release-to-device.sh` is the other half — dev-signed, for reproducing Release behaviour on a plugged-in phone, never uploadable.
- **No Expo account is committed** (`app.config.js`) — identity layers in from `EAS_OWNER`/`EAS_PROJECT_ID` or a gitignored `eas-project.json`, so push degrades to local-only banners on a fresh clone instead of breaking.
- **Self-update is a swap plus an exit, and the exit is the dangerous half** (`update/`). `check.ts` reads the latest release tag, `apply.ts` downloads it, verifies the published `.sha256` and *renames* it over `process.execPath`, `scheduler.ts` exits so a supervisor relaunches on the new inode. Three rules: the staging file is written **beside the target** (rename is only atomic within one filesystem, and `os.tmpdir()` is routinely another volume); it exits **only when `daemon.busyReason()` is undefined** (never mid-turn, never with a permission on screen); and it refuses unless `isCompiled()` — under `bun run`, `process.execPath` is the developer's **`bun`** binary, and a rename would replace the runtime every other project on that machine depends on.
- **A supervisor is what makes exit-to-update legal, and it is per-machine, not per-platform** (`cli/service*.ts`). All three have one — launchd `KeepAlive`, systemd `Restart=always`, and a Scheduled Task whose repeating trigger plus `IgnoreNew` policy is the same thing at one-minute granularity. Each must restart after a **clean** exit: `Restart=on-failure` and Task Scheduler's `RestartOnFailure` both ignore exit 0, which is exactly how the updater ends the daemon, so either would swap the binary and never come back. The gate is `supervisorInstalled()` — the service *file on disk*, not `process.platform`, because `pew2 serve` is a first-class command and a fresh install has no service until `pew2 setup` writes one. Windows additionally cannot unlink or replace a running `.exe`, only rename it, so the outgoing binary is parked aside and restored if the swap then fails. systemd needs `loginctl enable-linger` or the daemon dies at logout.
- **`pew2 setup --json` / `doctor --json` are the agent-facing surface** — `ok` is the stop condition, each problem carries a stable `id` and runnable `fix`, and missing secrets or LAN-only are `warning`, never `error`, so an agent can't loop on what it can't supply.
